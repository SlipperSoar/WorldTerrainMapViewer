# 功能介绍

## 行星地形图查看

### 导入

工具支持将自己的地形图通过`streamingAssets`目录导入，并可点击将其应用在“地球”上

如果有与地形图**配套的高度图**，同样可以导入，只需要按照规则命名即可自动生效。星球表面会根据地形图的高度图信息自动形成高低起伏的地形。

**高度图不会被列入可选的地形图列表**。

目录结构示例：
- streamingAssets/
  - my_world_terrain_map.png
  - my_world_terrain_map_height.png

### 查看

工具支持以下功能：

- 昼夜切换
- 季节切换
- 右键拖拽旋转视角
- 一键切换至特定视角
- 一键切换至特定季节
- 点击在星球表面打上标记
- 按键盘的字母区顶部的0-9数字按键，切换打标记使用的颜色
- 点击屏幕底部快捷键上方的标记预览列表中的特定标记，删除对应标记
- 顶栏「云层」开关：显示/隐藏由气候数据驱动的云层（见下方「云层预览」）

## 行星地形图生成

### 生成逻辑

本工具采用以下方式生成地形图

1. 提供一个随机种子，以种子为基础进行随机。（如果没有则使用本机时间作为种子）
2. 先在\[-10000m, 10000m\]范围内进行高度的随机生成：**域扭曲（domain warping）+ 多层分形噪声（fBm）+ 脊状噪声**，
   并按**地壳均衡**区分陆壳/洋壳（陆壳更厚更轻、整体抬升且起伏更大，洋壳平缓下沉）
3. 随机划分若干板块（球面 Voronoi），进行几次板块运动，计算板块运动造成的影响；
   陆壳碰撞隆起更强烈（造山带），洋壳俯冲则以海沟为主
4. **气候场**：海面按纬度蒸发水汽 → 按盛行风带向下风方向输送 → 内陆递减 + 迎风坡降水（雨影效应）
5. **侵蚀**：水力侵蚀（雨滴冲刷河谷、携带泥沙在下游与入海口沉积）+ 热力侵蚀（休止角），
   强度与降水耦合；侵蚀后重新标定海平面，并复算一次气候（气候 ↔ 地形一次反馈）
6. 依据侵蚀后的地形与气候计算**水系**（河网、湖泊、三角洲、季节性河流，见下）
7. 依据**地轴倾角**（地图属性，见下）推算永久雪线与冰盖范围：
   - 低纬度地区只有较高的山峰才有常年积雪
   - 纬度越高雪线越低，高纬度地区接近海平面即常年积雪
   - 极区形成连片冰盖，极地海面形成海冰
8. 计算**人文**（聚落 / 国家 / 交通 / 中文地名，见下）
9. 将高度图的灰度图保存至`streamingAssets`目录下
10. 根据高度、水系、冰盖与人文信息，生成对应的彩色地形图并保存

### 气候与侵蚀（贴近真实地球的部分）

- **风带经验公式**（由地轴倾角驱动）：太阳赤纬 `δ(λ) = arcsin(sin ε · sin λ)`（λ 为太阳黄经，
  春分为 0）→ 热惯性滞后 25 天得到 `δ_eff` → 热赤道 `φ_T = 30°·tanh(0.55·δ_eff/30°)`
  → 各风带中心 `φ_i = 基准纬度 + w_i·φ_T`（副高 ±30°、西风 ±45°、极地东风 ±65°，
  w 分别 0.50 / 0.35 / 0.15）→ 半球强度 `S_N = 1+0.4·(−δ_eff/ε)`、`S_S = 1+0.4·(δ_eff/ε)`
- **倾角决定气候带宽度**：把上面的公式按全年取样平均，得到每条纬线的年平均水汽供给。
  倾角为 0° 时退化为固定风带（赤道 1.00、15° 仅 0.11 —— 极窄的赤道雨林与紧邻的沙漠带）；
  倾角越大，各带一年中摆得越远、平均后的湿/干带越宽（15° 处：23.44° 时 0.32、45° 时 0.39）
- **盛行风带输送**：信风（0-30°）自东向西吹向赤道、西风带（30-60°）自西向东吹向极地、
  极地东风（60-90°）自西向东吹向赤道；水汽沿风向逐格输送，越深入内陆越干燥（大陆性）
- **雨影效应**：气流爬坡时按抬升高度拦下水汽（迎风坡多雨），背风坡因此干旱 ——
  山脉两侧出现干湿反差，沙漠多出现在内陆与背风侧
- **水力侵蚀**：数十万颗雨滴沿坡面下泄，按携沙能力冲刷（湿润区更强）并把泥沙沉积到
  下游、洼地与入海口，自然雕出 V 形谷、冲积扇与三角洲
- **热力侵蚀**：坡降超过休止角时物质向低处移动，陡崖变缓、坡面更自然
- **地壳均衡**：低频噪声决定陆壳/洋壳，陆壳整体抬升且起伏更大，洋壳平缓下沉；
   海陆比例最终由水面占比归一化保证
- 实测（1024×512 合成世界）：气候场 + 投影后细尺度侵蚀合计 **0.17 s**（气候 11 ms + 侵蚀 162 ms），
  2048×1024 下 **0.51 s**；这两步对地形的平均改动 |Δh| ≈ 18 m、最大 ≈ 2.0 km，
  26% 的格子改动超过 20 m（2048×1024 下分别是 11 m / 2.6 km / 16%）

### 水文（河网、湖泊、三角洲）

水系不是逐条「从山头往下画」，而是先建立全域的汇流关系，再由流量决定河宽：

1. **填洼与流向**：以海洋为起点做 Priority-Flood，把内陆洼地填平，同时确定每一格的唯一流向。
   这样任何一格都必然有一条单调下降的路径入海，河流不会倒流或凭空断掉。
   排序键上加了一个很小的相干扰动，用来打散平地上的网格状直河道，使水系自然蜿蜒
2. **汇流累积**：按水面高程从高到低把水从上游累加到下游。本地产流与地形高度相关（高山降雨/融雪更多），
   并按湿度缩放（干旱区产流很少）
3. **河宽由流量决定**：`河宽 = 0.7 + 1.25·((Q/Q₀)^0.52 - 1)` 像素（上限 12 像素）
   - 多条支流汇合 → 流量跃升 → **河面变宽**
   - 主干在平缓段分流 → 流量被分走 → 两支都**收窄**
   - 干流还会按宽度加粗掩膜，使它在图上真正比支流宽出好几个像素
4. **分流（辫状/分汊）**：在水面坡降很小的冲积平原段，允许河道把一部分流量分给第二个去向，
   形成「主干分出支流」的分汊河段
5. **湖泊**：填洼时被抬高的**闭合洼地**才算候选，够不够格成湖由**水量平衡**决定 ——
   湿润度越高、盆地越大越深就越可能积水，干旱区的大盆地常常只是干盆地（盐湖/滩地），
   再叠一层与地图种子绑定的稳定随机，于是湖的"有大有小"是自然分布而不是一刀切。
   具体门槛：候选盆地面积 ≥ 3「赤道等效格」、最大水深 ≥ 6 m；蓄水后水位淹不到 2 m 的浅滩仍按陆地处理。
   面积按行权重 `cos(lat)` 折算成真实球面面积，因此在任意纬度都代表同样的物理大小
6. **三角洲**：河道入海处，若前方是浅海（水深小于 900 m），会分出 2–5 条分流河道呈扇形铺开，
   河越宽三角洲越大；水太深则冲刷不出三角洲
7. **季节性河流**：集水区平均湿度低于半干旱上限、且属于本地河网中最干的那四分之一时，
   河道标记为季节性（间歇性）河流，在图上以更淡的沙蓝色绘制 —— 湿润世界几乎没有，干旱世界大量出现
8. **干旱区沿途渗漏**：河道经过干旱区时流量按比例衰减，因此沙漠中的河流可能中途消失或越走越细

### 人文（聚落、国家、交通、中文地名）

生成链路：`自然地理 → 宜居度 → 人口势场 → 聚落 → 国家 → 人口 → 中文命名 → 交通网络`

1. **宜居度**：由最热月气温适宜度、湿度、靠近河湖、靠海、地形起伏共同决定，并扣除洪涝与严寒
2. **人口势场** = 宜居度 × 多尺度噪声（所以人口不是随机撒点）
3. **聚落**：按势场加权的泊松盘采样 —— 势场越高越密，等级越高间距越大；等级分 都 / 城 / 镇 / 村
4. **国家**：人口最大的若干聚落作首都，用**成本距离**竞争出势力范围（山脉与海洋昂贵、河谷便宜），
   于是国界会自然沿山脉、河流与海岸展开
5. **人口**：先算每个聚落的腹地人口（多源成本距离划分腹地），再套 **Zipf 律**：
   第 r 大城市人口 ≈ 最大城市人口 / r^0.9
6. **中文命名**：`地理特征 → 命名风格包 → 词库 → 模板组合 → 过滤去重`。
   风格包按气候/地形选取（北境寒地 / 中原农耕 / 海岛贸易 / 沙漠游牧 / 南方水乡 / 山地矿镇），
   后缀按等级与功能匹配（港/津/埠、关/隘、矿/盐、京/都…），
   并做长度、专名重复、同音、连续同字、语义冲突过滤 —— 沙漠里不会出现「某某港」，雪原不会出现热带词
7. **交通网络**：引力模型（人口积 ÷ 距离^γ）排序 → 最小生成树保证连通 → 追加高强度边 →
   在成本场（坡度、海洋、河谷）上寻路，得到陆路 / 河运 / 海运三种交通线
8. **保存与叠加显示**：
   - 完整数据保存为 `<地图名>_human.json`（聚落、国家、交通线、自然地名、势力范围栅格）
   - 摘要写进地图属性 `<地图名>_meta.json` 的 `human` 字段（数量与总人口）
   - 载入地图时叠加显示在地球表面：**势力范围染色 + 国界 + 交通线 + 聚落点 + 城镇中文地名标签**，
     顶栏的「人文」开关可以整体显隐
   - 地名标签只显示**朝向相机的那一面**：镜头转到另一侧时自动消失，转回来再出现；
     靠近地平线时按球面可见性（`n·相机方向 > R/D`）渐隐，避免生硬地跳出

### 地图属性（地轴倾角）
**地轴倾角**（黄赤交角，0°-90°）是一张地形图自身携带的属性，在生成时通过界面上的滑动条设定：

- 影响光照：倾角越大，极地的季节差异越剧烈；倾角为 0° 时没有季节变化
- **四季的太阳赤纬**与生成时用的是同一个公式（`ClimateModel.SolarDeclination`）：
  `δ(λ) = arcsin(sin ε · sin λ)`，λ 为太阳黄经（春分 0°、夏至 90°），
  于是日下点纬度一年内正好在 `[-ε, +ε]` 之间往返：

  | y（年内位置） | 0（春分） | 0.25（夏至） | 0.5（秋分） | 0.75（冬至） |
  |---|---|---|---|---|
  | 日下点纬度 | 0° | **+ε** | 0° | **−ε** |
  | N45° 正午太阳高度（ε=23.5°） | 45.0° | **68.5°** | 45.0° | **21.5°** |

  运行时阳光方向的季节俯仰取 **`θ = ε − δ`**：因为倾角是施加在「地球」上的，
  俯仰要同时抵消地球那侧的倾斜、再给出目标赤纬（摆角 θ 时，日下点纬度 = ε − θ）。
  实测 ε = 0 / 23.5 / 45 / 90 四种倾角下，日下点纬度与 `δ` 的最大偏差都是 **0.000°**；
  ε=0 时四季完全消失、ε=90 时出现真正的极昼极夜。
  热惯性滞后（25 天）只用于气候场（气温/风带对辐射的响应有延迟），
  不参与光照 —— 阳光的几何位置不该被滞后。
- 影响冰盖：倾角越大，高纬夏季越暖、雪线越高，冰盖越向极地退缩；倾角越小，雪线越低、冰盖越向低纬扩展
- 雪线（终年积雪下限）由纬度与倾角的半经验公式给出（λ=|纬度|、ε=地轴倾角，单位 km）：

  ```
  海平面最热月平均气温  T_s = 28 - 0.0055·λ² + 1.0·(ε-23.44)·(λ/90)²      [℃]
  雪线中值              H_m = max(T_s, 0) / 5.5                            [km]
  雪线区间              H_min = max(0, H_m-(0.7+0.012λ))                   湿润（海洋性）
                        H_max = H_m+(1.0+0.022λ)                          干旱（内陆）
  ```

  生成时用地图自身的湿度场在区间内插值：湿润山地取低雪线、干旱内陆取高雪线，因此积雪分布会随气候带自然起伏
- 冰盖与海冰界限同样由该公式推得：最热月平均气温 ≤ 0℃ 的纬度即海平面终年积雪（陆地冰盖）界限，更冷约 2℃ 处为海冰界限
- 公式给出的是真实海拔（赤道约 5.1 km），而生成地图的起伏更小（合成世界 1024×512 实测最高陆地约 5.8 km、
  多数地图在 1~6 km 之间），因此雪线按「地图最高陆地海拔 ÷ 地球陆地最高海拔 8848 m」等比标定后使用，
  这样公式里的纬度、倾角与干湿差异都能在同一比例下体现

生成时会在地形图旁写入元数据文件 `<地图名>_meta.json`（记录地轴倾角、水面占比、种子等）。载入该地图时，工具会自动读取并应用其中的地轴倾角；没有元数据文件的地图按默认值 23.5° 处理。

> 侧边栏中的地轴倾角滑动条是**下一次生成**的参数，拖动它不会改变当前星球显示的倾角。
> 星球始终坚持显示当前所选中地图生成时使用的倾角，只有在「生成完成」或「切换到另一张地图」时才会改变。
> 如果生成过程中又拖动了滑动条，生成结束后滑动条会自动回到本次实际使用的数值。

### 云层预览

在星球外侧套一层略大的半透明球壳（默认高出地表 **0.12 倍星球半径**），云的分布**不是随机的**，而是由地图自身的
气候场驱动 —— 湿地多云、沙漠几乎无云，并随风带流动、随季节南北移动。
顶栏「云层」开关控制显隐（默认关闭）。

用到的气候数据与对应实现（着色器 `Assets/Shaders/CloudLayerShader.shader`，
组件 `Assets/Scripts/CloudLayer.cs`）：

| 气候数据 | 云层的表现 | 实现 |
|---|---|---|
| 湿度场（风带 + 雨影算出的 `moisture`） | 湿区云浓、干区云稀 | 覆盖率 `coverage = 0.65 × lerp(0.25, 1, 湿度)`，阈值 `1 − coverage` |
| 水体（河网 / 湖泊 / 三角洲） | 水体上空与下风更易成云 | `_WaterTex` 叠加到水汽（`_WaterInfluence`） |
| 盛行风带（信风 / 西风 / 极地东风） | 云带随风向东/西漂移，且方向随纬度反向 | `WindBand(lat)` 给出 ±1 的东西向流速，再偏移噪声采样经度 |
| 地轴倾角与四季 | 云带随季节南北摆动 | 季节滑条 → `SetSeasonProgress` → `_SeasonShift`（±0.35 的纬度位移） |
| 太阳方向 | 向阳面亮、背阳面暗、靠太阳一侧有银边 | `_SunDirection` + `_LightDirection` 散射 |

云的形状用**多层 FBM 值噪声**（6 层基础 + 4 层细节）。值噪声的分布集中在 0.5 附近
（实测 p10≈0.23 / p50≈0.49 / p90≈0.77），所以着色器里先把它归一化到 0-1
（`_NoiseFloor` / `_NoiseCeil`）再与覆盖率比较 —— 不归一化就只有最密的尖峰能成云。

实测（合成世界 1024×512，离线校验台把着色器逐式移植后计算）：

| 覆盖率 | 干区云量（湿度<15%） | 湿区云量（湿度>70%） | 全图平均 | 云覆盖 |
|---|---|---|---|---|
| 0.42 | 0.006 | 0.189 | 0.032 | 3.1% |
| **0.65（采用）** | **0.017** | **0.544** | **0.093** | **8.9%** |
| 0.85 | 0.040 | 0.876 | 0.176 | 17.2% |

按纬度带（用采用值）：湿带云多、副热带少云，与风带结构一致 ——
**84°N 0.442 / 48°N 0.247 / 12°N 0.079 / 24°N 0.032 / 24°S 0.022 / 72°S 0.021**。
想调云量只需改「云层」组件的**基准云量**滑条（0-1），一个数即可。

> 方案原文（`云层效果实现方案.md`）是针对 Three.js 写的，这里按其思路移植到 Unity：
> `ShaderMaterial` → `Material` + `.shader`；`DataTexture` → `Texture2D`（`TextureFormat.R8`）；
> `uniforms.uTime` → 内置 `_Time`；`side: BackSide` → `Cull Off`。
> 体积光线步进（Ray Marching）没有采用 —— 本项目是「预览」场景，单层壳 + FBM 足够，
> 也避免了移动端/低端机的帧率风险；如果以后要体积感，可以在此基础上加步进。

**湿度场的传递**：湿度场没有单独落盘，生成时会降采样成 256×128（每格 1 字节）后
存进已有的 `<地图名>_human.json`（复用 base64 机制，不新增文件）。
载入地图时 `EarthManager` 会把它推给云层；没有人文数据的老地图则退化为「均匀云量」。

**接法**：在场景里给挂了 `EarthManager` 的物体（或它的子物体）加一个 `CloudLayer` 组件即可，
`earthRenderer` / `sunLight` 留空时会自动从场景里找。顶栏的「云层」开关会自动出现在
「地形凹凸」右边（开关初值取自云层**实际**显隐状态，不会出现「没勾选却显示」）。

#### 球壳尺寸是怎么定的

`shellThickness`（默认 **0.12**）是**高出地表的厚度**，单位是星球半径的倍数，不是绝对尺寸。
下限强制 0.02：地形顶点位移最大可外凸 `_HeightScale`（`EarthManager.heightScale`，默认 0.15）
倍半径，太薄会被山峰穿破。实测最高陆地 4431 m 的图，峰值外凸约 **0.0665 倍半径**，
所以 0.12 有接近一倍的安全余量。

半径的取法有两个坑，代码里都绕开了（见 `CloudLayer.GetEarthWorldRadius` / `ApplyScale`）：

1. **不能照抄 `earth.localScale`** —— 星球网格的顶点半径不一定是 0.5，还可能有非等比例缩放。
   本项目就是 `Sphere.fbx`（网格半径 0.1）配 `localScale = 20`，照抄会算错一个数量级。
2. **不能读 `Mesh.vertices`** —— 导入模型默认没开 Read/Write，会报
   `isReadable is false`；也不能用 `Renderer.bounds`，它**把子物体（标点/标签/地名文字）也算进去**
   （实测星球真实半径 2.000，而 `Renderer.bounds` 给 2.632）。

正确做法是用 `Mesh.bounds`（本地包围盒，不需要 Read/Write）× 世界缩放：

```
星球世界半径 = max(Mesh.bounds.extents) × max(|lossyScale|)        // 0.1 × 20 = 2.000
云层本地缩放 = 2 × 星球世界半径 × (1 + shellThickness) / 父级等比缩放  // 2×2×1.12/20 = 0.224
```

### 使用方式

#### 自己生成

1. 鼠标移动到画面左侧，引出侧边栏
2. （可选）填写用于生成的随机种子
3. 调整星球的水面占比
4. 拖动**地轴倾角**滑动条设置本次生成要使用的地轴倾角（0°-90°）
5. 点击生成，等待进度100%（完成）后自动应用至星球预览，此时星球的倾角即为该地图的倾角

#### 查看他人分享的地形

**本地文件方式**

1. 将他人分享的地形图添加进`streamingAssets`目录下
2. （可选）将他人分享的对应高度图也添加进`streamingAssets`目录下
3. （可选）将他人分享的对应元数据文件 `<地图名>_meta.json` 也添加进`streamingAssets`目录下，即可自动还原该地图的地轴倾角
4. 运行工具，鼠标移动到画面左侧，引出侧边栏
5. 在侧边栏下方列表中，点击选中刚刚添加的地形图即可

**自行生成方式**

1. 得到他人生成地形图时使用的**随机种子**（如生成时没有填写，则生成后会将使用的随机种子显示在种子的输入栏）
2. 得到他人生成地形图时使用的**水面占比**
3. 得到他人生成地形图时使用的**地轴倾角**
4. 运行工具，鼠标移动到画面左侧，引出侧边栏
5. 将得到的随机种子填写进侧边栏顶部的种子输入框中

8. 点击生成按钮后等待结果即可

## 附：球形生成域

生成域已从矩形网格迁到**单位球面等面积网格**（细分二十面体）：先用 3D 噪声在球面格点上生成大地形
（板块 / 陆壳 / 地壳均衡 / 中细尺度细节），再做球面排水（Priority-Flood 填洼 → 沿填洼面选流向 →
拓扑累积 → 按汇水量下切河谷）与球面侵蚀（雨滴 + 热力），最后投影成等距圆柱图。
密度由 `SphericalTerrainGenerator.MaxSphereCells` 决定（1024×512 → level 7 约 0.95 s；
2048×1024 → level 8 约 2.8 s）。旧路径可用 `WorldGenConfig.planarGeneration = true` 回退。

- 已球面化：地形、排水、侵蚀、气候（按 cos(lat) 折算公里的物理水汽衰减）、河网判据（球面径流 + 分位阈值）
- 湖泊 / 三角洲的提取仍在投影网格上：湖泊的面积门槛按行权重 `cos(lat)` 折算成**真实球面面积**，
  三角洲用的是绝对深度门槛，两者都没有纬度失真（`HydrologyGenerator.MarkLakes` / `CarveDeltas`）
- 人文成本距离仍在粗网格上跑，但步长是**真实几何长度** `√((dx·cosφ)² + dy²)`，
  腹地人口、势力范围、交通线寻路共用这一个度量（`HumanGeographyGenerator.StepLength`）

### 板块边界影响：必须和板块归属用同一个位置

`SphericalTerrainGenerator` 里板块归属用**噪声扰动后的位置**做球面 Voronoi
（`PerturbedPlatePosition`），而边界影响原先改用**未扰动的位置**去量「最近/次近板块」。
两者错配会产生一种很隐蔽的悬崖：

- 归属被扰动推到邻近板块域的格点，其「本格所属板块」可能根本不是最近的板块，
  于是 `d2 - d1 < 0`；旧代码把这种情况当作「离边界很远」直接 `continue`（不抬升），
  而**相邻格**归属正常、拿到满幅隆起 —— 相邻两格高差可达上万米。

实测（`Assets/StreamingAssets/gen_rnd_20261015_233702`，2048×1024，seed -1705560046）：

| 指标 | 旧口径 | 统一位置后 |
|---|---|---|
| 边界影响场峰值 | 14,357 m | **1,672 m** |
| 该场相邻最大跳变（平滑前） | 16,439 m | **1,642 m** |
| 该场相邻最大跳变（14 趟平滑后） | 3,163 m | **309 m** |
| 陆地相邻最大高差（加边界影响后） | 3,161 m | **402 m** |
| 最终最高陆地 | 13,683 m | **2,903 m** |

修复只是让度量与归属同源，并让 `gap < 0` 归一成"正好在边界上"（而不是当成"离边界很远"跳过）；
边界影响场仍覆盖全部格点（隆起/沉降格数几乎不变：299,501 vs 299,484），
所以板块边界的造山/裂谷结构保留了，只是幅度从"平均 |值| 1320 m"收敛到"330 m"。

**落到图上的效果**（同一张图、同一种子重生成，按纬度带统计陆地局部最大高差）：

| 纬度带 | 修复前最大 / >500 m 占比 | 修复后 |
|---|---|---|
| 0~27° | 941 m / 0.34% | **269 m / 0.00%** |
| 27~45° | 2039 m / 5.16% | **257 m / 0.00%** |
| 45~60° | 2118 m / 3.28% | **203 m / 0.00%** |
| 60~76° | 1255 m / 1.31% | **218 m / 0.00%** |
| 76~90° | 1961 m / 1.49% | 1315 m / 1.44%（**残余**） |

中低纬的"非板块边界大规模悬崖"全部消除。76~90° 还剩一处 1315 m —— 出现在**极点行**
（地图最上/最下一行），是投影栅格化在极点附近的退化行为，与本次修复无关，尚未处理。

> 注意这次修复改变了地形观感：`waterCoverage` 不变的前提下，合成世界 1024×512 的
> 陆地占比 40.7% → 40.3%、平均坡降 35.0 → 30.4 m/格、最高陆地 5805 → 4910 m。
> 旧值里有相当一部分是那个数值错配抬出来的假高度。

#### 边界幅度随板块运动强度缩放

修好错配之后边界隆起一度衰减到"平均 |值| 91 m、峰值 1.7 km"，山脉变得不明显。
按「板块边界的高山与鸿沟来自板块运动、幅度视运动强弱而定」这一依据重新标定：

- 四档系数提成具名常量：`UpliftConvergentContinental` 700 / `UpliftConvergentOceanic` 250 /
  `SubsidenceDivergentContinental` 400 / `SubsidenceDivergentOceanic` 500（米）
- **幅度乘以相对运动速度**：`driftStrength = (driftSpeed_own + driftSpeed_other) / (2 × 1.25)`，
  而 `driftSpeed ∈ [0.5, 2.0]` —— 运动激烈的边界给出约 1.6 倍的高山，平静的边界只有约 0.4 倍
- 板块**内部**的起伏不经此处：那是大地形噪声（域扭曲 fBm + 中/细尺度细节）与地壳均衡的职责

标定过程与实测（`gen_rnd_20261015_233702` 同种子重生成，2048×1024，海拔分位均为陆地格）：

| 陆汇 / 洋汇 / 陆张 / 洋张 | 场峰值 | p50 | p90 | p99 | 最高 | >2000 m 占比 |
|---|---|---|---|---|---|---|
| 400 / 150 / 250 / 300 | 438 m | 924 | 1543 | 1936 | 2507 m | 0.7% |
| **700 / 250 / 400 / 500（采用）** | **767 m** | **889** | **1711** | **2002** | **2596 m** | **1.0%** |
| 1000 / 380 / 550 / 650 | 1096 m | 875 | 1921 | 2167 | 2722 m | 6.0% |
| 2500 / 900 / 1200 / 1400 | 2739 m | 1125 | 2985 | 3197 | 3618 m | **36.9%（高山过多，已否决）** |

> 曾经一度把系数提到 2500/900/1200/1400，结果 `>2000 m` 的陆地占了 **37%**、
> 出图后陆地大半是橙棕"山地色"（陆地配色在 1500 m 就进入橙棕、5000 m 才是雪）——
> 这就是"高山占比太多"的直接原因。**边界隆起是一次性的造山带，不该把整片大陆抬起来**：
> 系数回到 700/250/400/500 后 `>2000 m` 降到 1%，同时 p50 仍落在合理区间。
