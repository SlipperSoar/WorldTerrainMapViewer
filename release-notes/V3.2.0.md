行星渲染改造步骤 2 的第一部分：把数据图接进运行时、加上**独立大气球壳的 Fresnel 边缘辉光**，并把 `_surface.png` 的 G 通道从二值掩膜升级成水体分类。同时砍掉「只有 PNG、没有配方」的老地图，并保留一个独立的 PNG 导入入口。

其它：

- `Assets/UI/SimHeiFontAsset.asset` 的 YAML 标签由团结引擎 `yousandi.cn,2023` 归一为 Unity `unity3d.com,2011`（图像数据不变，`m_CompleteImageSize` 仍为 1048576）。这是 Unity 打开工程时必然产生的格式迁移，随本次一并提交，避免每次构建都留下脏文件

数据契约修订（G 通道）：

- `_surface.png` 的 G 从 `0/255` 二值掩膜改为**水体分类**：陆 / 深海 / 海 / 浅海 / 湖 / 河 / 季节河 / 三角洲 / 海冰 / 冰川 / 雪峰（10 类 + 陆地）
- 用**间隔编码**（`WaterClass` × 16）而非直接存 0..10：归一化后每类占一个平台，误用 Bilinear / sRGB 也不会把「河」抹成「海」；解码 `round(G/16)`
- `SurfaceDataLayers.ClassifyWater(TerrainType)` 是唯一的「类型 → 分类」映射；roughness 等处复用 `IsWater`
- 生成语义完全不变（11 个 dump 指纹逐位一致）

步骤 2.0（运行时接入）：

- `UIController.DecodeTexture` 支持 linear 与 Point 过滤；数据图按 linear 载入避免 gamma 污染数值，surface 用 Point 避免分类值被插值
- `EarthManager.SetSurfaceData` 把 `_SurfaceTex` / `_DetailTex` 与 6 个渲染参数（海平面 / 三条雪线 / 潮汐）挂到地表材质；缺图时关掉 `_SURFACE_DATA_ON`
- `EarthSurfaceLitShader` 的 ForwardBase pass 接收数据图与渲染参数；ForwardAdd 是叠加 pass，不重复加辉光
- 所有 PNG 强制上北下南，`FlipVertical` 改为无条件（Unity `LoadImage` 行序约定，不再是兼容选项）

Fresnel 边缘辉光（独立大气球壳）：

- 新增 `Custom/AtmosphereGlowShader` + `AtmosphereGlow.cs`：一层半径 ×1.16 的透明球壳
  （比云层的 ×1.12 更大），`Queue=Transparent+10` + 加色混合，辉光始终是最外一圈
- 球壳由 `EarthManager.Awake` 自动创建并跟随星球缩放；不改场景文件
- **与地形凹凸、云层显隐彻底解耦**：凹凸任意开、云层任意开关，辉光都不受影响
- 颜色 / 边缘衰减 / 强度 / 向阳增强在组件上可调；`EarthManager` 暴露开关与调节 API
- 地表 shader 不再计算 Fresnel（此前贴着位移表面、又被云层盖住，是首轮实测的问题）

砍掉老地图：

- 「地图 = 一份整型配方 `_meta.json`」。`MapMetaData.Load` 只接受 `version>=3` 且带配方的 meta；无配方 / v1~v2 meta / 只有 PNG 的快照都不再载入
- 删除 `pngNorthUp` 字段、`ToRecipe()` 的无配方折算分支、`GetRenderParams()` 的 `version<3` 兜底
- 地图列表只列有效 meta；保留「只有配方、无 PNG」的按配方重建（2.9 起主流方式）
- `ClampAxialTilt` 的 NaN 防御保留

独立 PNG 导入入口（保留想查看单张图的能力）：

- 侧栏新增「导入 PNG 查看」：编辑器弹系统文件选择框；打包后的播放器读 `StreamingAssets/import.png`
- 构造最小 `MapData`（只有地形图、无配方），不进地图列表、不要求 meta、不载入标注、不参与导出

实测反馈修复（两轮）：

- **首轮·辉光看不见**：材质参数实测正常，根因是 `pow(1-NdotV,3)` 可见带过窄。调亮参数后
  辉光出现，但贴在地表、被云层盖住 → 见第二轮
- **首轮·导入 PNG 显示混乱**：无高度图时 `_TERRAIN_DISPLACEMENT_ON` 仍开着，shader 采样 null
  高度图得到恒定 -1 高度，导致球面整体位移 + 法线退化。`ClearEarthHeightMap` 现在同时关 keyword，
  并新增 `_hasHeightMap` 状态：位移只在「用户想开凹凸 且 确实有高度图」时启用；无高度图时
  导入路径还会把「地形凹凸」开关关掉，手动打开也不会异常
- **第二轮·辉光贴着星球、开凹凸几乎不可见、应在云层外**：把 Fresnel 从地表 shader 移到
  独立的 ×1.16 大气球壳（`AtmosphereGlowShader` / `AtmosphereGlow.cs`），加色混合、最后渲染，
  与凹凸和云层彻底解耦
- 顺带修 `_SURFACE_DATA_ON` 的 global/local keyword 不匹配（`multi_compile` → `multi_compile_local`），
  并在 `SetSurfaceData` 加自检日志

验证：

- 编译门 0 错误；Unity 2022.3.62f3c1 `COMPILE_OK`，C# 与 shader 均无错误
- Windows 播放器构建 `BUILD_OK`（147 文件 / 117.2 MB），无 shader error
- 11 个地形 dump 与基线逐位一致
- stepcheck / resolutioncheck / biomecheck / planetcheck 全部通过
- Unity 内探针全绿：5 层 PNG 落盘、七件套齐全、meta 渲染参数自检、G 通道分类值合法、无配方 meta 被拒绝、同一配方两次生成逐位一致
- 导出的 PNG 经外部库解码校验：CRC / 方向 / 通道 / 水体分类间隔编码
